# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 이 저장소의 성격

코드베이스가 아니라 **업무 문서 아카이브**다. 살림풍경커머스(이하 살림풍경) MD팀에서 김도윤 대리가
2026년 9월 말 타 부서로 이동하며 남긴 인수인계 자료 모음이다. 빌드·테스트·린트 명령이 없고,
git 저장소도 아니다. 작업은 대부분 "문서를 읽고 → 사실을 대조하고 → 정리/요약/문서 작성"이다.

작성자가 정리를 끝내지 못한 상태로 넘긴 자료라 **같은 사실이 여러 파일에 서로 다른 값으로**
남아 있다. 어떤 숫자든 인용하기 전에 아래 "진실 공급원" 규칙을 먼저 확인할 것.

## 진실 공급원 (source of truth)

- **대성물산 공급 단가**: 아직 정하지 않았다. 단가표 5개(내용 3종)가 서로 다른 값을 적고 있어
  아래 "확인 필요"에 올려 두었다. 파일명(`최종`·`진짜최종_v2`)만 보고 답하지 말 것.
- **계약 조항**: `거래처/*/계약서_*.md`는 MD팀이 옮겨 적은 **요약본**이다. 조항 해석에 이견이 있으면
  원본 PDF(총무팀 계약 보관함)가 우선한다고 문서 스스로 명시하고 있다.
- **소비자 판매가 vs 공급 단가**: `거래처/대성물산/제품카탈로그.json`의 `listPrice`는 살림풍경
  **판매가**다. 공급 단가와 혼동하지 말 것 (텀블러 판매가 15,900원은 공급 단가가 아니다).
- **CS 반품 기간**: 확정된 최신값을 단정하지 말 것. `매뉴얼/CS응대매뉴얼_진짜최종_v2.docx`가 최신
  버전이라고 인수인계 메모에 적혀 있으나, 값 자체는 docx를 열어 확인해야 한다(아래 "바이너리 문서" 참고).

## 확인 필요 (미확인 — 판정 보류)

아래는 인수인계 시점에도, 이후 조사에서도 확정하지 못한 항목이다. **추측으로 메우지 말 것.**

- **대성물산 단가표 중 어느 것이 현행인지** — 단가표 5개(내용 3종: 2026-01-10 8,900원 ·
  2026-04-03 9,200원 · 2026-06-15 9,500원)가 `거래처/대성물산/`과 `회의록/`에 흩어져 있다.
  파일명으로는 정할 수 없다. 회의록·이메일과 대조하기 전에는 판정하지 않는다.
- **CS 반품 기간의 최신 확정값** — `CS응대매뉴얼_진짜최종_v2.docx`를 열어야 알 수 있다.
  `반품교환프로세스.md`의 7일은 2025-06 기준 구값이다.
- **`CS응대매뉴얼_진짜최종_v2 (1).docx`가 바이트 동일 사본인지** — 크기만 같은 것을 확인했다.
  `md5`/내용 대조 전에는 삭제 금지.
- **매출보고 docx 2종 중 최신본** — 파일명("_최종")은 이 저장소에서 근거가 되지 않는다.
  문서 내부 작성일로 판정해야 한다.
- **`거래처/초록별상사_제안서.pptx` ↔ `거래처/초록별상사/신규거래처_소개자료.docx`** — 같은 거래처
  자료가 상위/하위 폴더에 흩어져 있다. 형식이 달라 중복이 아닐 수 있음, 내용 미확인.
- **`2024년 자료(안씀)/예전_거래처_리스트.xlsx`** — 현행 거래처 정보와 중복 가능성. 폴더명이 이미
  "안씀" 상태 표시라 우선순위는 낮다.
- **DSM-SP100 재고 -32개의 원인** — 반품 처리 지연 관련 가능성만 기재돼 있다.
- **초록별상사 샘플 회신 여부** — 2026-09-05 미팅 이후 진행 상황을 아는 담당자가 없다.
- **`거래처/새 거래처 후보/스캔0002.pdf`** — 이름만 봐서는 무엇인지 알 수 없다. 내용 미확인.

참고: `보고서/매출데이터_2026Q2.csv`와 `카테고리별_매출현황_2026Q2.html`은 중복이 아니라 같은
데이터의 두 표현(원자료 ↔ BI 내보내기)이며, 품번별 합계가 카테고리 합계와 일치함을 확인했다.

## 파일 명명 관행 (읽는 법)

- `최종`, `진짜최종`, `v2`, `- 복사본`, `(수정)`, `(초안)` 접미사는 **버전 순서를 나타내지 않는다.**
  파일 내부의 `작성일`/`비고` 컬럼, 회의록 날짜, 이메일 Date 헤더로 판단할 것.
- 단가표 CSV 스키마는 거래처 공통: `품번,품명,단가(원),MOQ(개),리드타임(일),작성일,비고`.
  `작성일` + `비고`가 사실상 버전 메타데이터 역할을 한다.
- 회의록 파일명은 `YYYY-MM-DD_주제.md`. 이 규칙을 안 지킨 파일(`회의록(수정).md`,
  `단가표_최종.csv`)은 잘못 놓인 파일일 가능성이 높다.

## 바이너리 문서 다루기

`.docx`, `.pptx`, `.xlsx`는 Read 툴로 열리지 않는다(`.pdf`는 Read로 열리지만 스캔본은 텍스트가
거의 안 잡힌다). 내용이 필요하면 압축 해제 후 XML에서 텍스트를 뽑아야 한다:

```bash
python3 -c "
import zipfile,re
z=zipfile.ZipFile('매뉴얼/CS응대매뉴얼_진짜최종_v2.docx')
x=z.read('word/document.xml').decode('utf8')
print(re.sub(r'<[^>]+>','',re.sub(r'</w:p>','\n',x)))"
```

pptx는 `ppt/slides/slide*.xml`, xlsx는 `xl/sharedStrings.xml` + `xl/worksheets/sheet1.xml`.
샌드박스에서 이 명령은 승인이 필요할 수 있다.

## 작업 시 지켜야 할 것

- 숫자(단가·기간·재고)를 답변에 쓸 때는 **출처 파일명과 작성일을 함께 밝힌다.** 이 저장소에서는
  같은 숫자가 서로 다른 값으로 최소 3벌씩 존재한다.
- 원본 파일을 덮어쓰거나 지우지 않는다. 작성일이 이른 판(`단가표_진짜최종_v2.csv` 등)도 인수인계
  이력의 일부이므로, 정리하라는 지시가 있어도 지우지 말고 확인부터 한다.
- 회의록·계약서·이메일은 사실 기록이다. 요약·재구성 산출물은 새 파일로 만들고 원본은 남긴다.
- 미해결 항목을 발견하면 추측으로 메우지 말고 "미확인"으로 표시한다 — 원 작성자도 그렇게 남겼다.
