# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## 이 저장소의 성격

코드베이스가 아니라 **업무 문서 아카이브**다. 살림풍경커머스(이하 살림풍경) MD팀에서 김도윤 대리가
2026년 9월 말 타 부서로 이동하며 남긴 인수인계 자료 모음이다. 빌드·테스트·린트 명령이 없다.
작업은 대부분 "문서를 읽고 → 사실을 대조하고 → 정리/요약/문서 작성"이다.

2026-10-05부터 **git으로 버전 관리한다.** 첫 커밋 `정리 전 상태`가 손대기 전의 원본 스냅샷이므로,
그 이후의 정리 작업은 diff로 되짚을 수 있고 잘못 지운 파일도 복원할 수 있다. 파일을 옮기거나
이름을 바꿀 때는 `git mv`를 써서 이력을 잇는다. 한글 파일명이 8진 이스케이프로 깨져 보이면
`git config core.quotepath false`를 설정할 것. 예제 저장소의 스냅샷에서 시작했다면 `.git`이 없으니
먼저 `git init`과 시작 커밋을 만든다(예제 저장소의 ch17/README.md 참고).

작성자가 정리를 끝내지 못한 상태로 넘긴 자료라 **같은 사실이 여러 파일에 서로 다른 값으로**
남아 있다. 어떤 숫자든 인용하기 전에 아래 "진실 공급원" 규칙을 먼저 확인할 것.

## 진실 공급원 (source of truth)

- **대성물산 공급 단가**: 아직 정하지 않았다. `거래처/대성물산/단가표/`의 세 파일이 서로 다른 값을
  적고 있어 아래 "확인 필요"에 올려 두었다. 파일 하나만 보고 답하지 말 것 — 회의록·메모·이메일까지
  대조해야 한다.
- **계약 조항**: `거래처/*/계약서_*.md`는 MD팀이 옮겨 적은 **요약본**이다. 조항 해석에 이견이 있으면
  원본 PDF(총무팀 계약 보관함)가 우선한다고 문서 스스로 명시하고 있다.
- **소비자 판매가 vs 공급 단가**: `거래처/대성물산/제품카탈로그.json`의 `listPrice`는 살림풍경
  **판매가**다. 공급 단가와 혼동하지 말 것 (텀블러 판매가 15,900원은 공급 단가가 아니다).
- **CS 반품 기간**: 확정된 최신값을 단정하지 말 것. `매뉴얼/CS응대매뉴얼_진짜최종_v2.docx`가 최신
  버전이라고 인수인계 메모에 적혀 있으나, 값 자체는 docx를 열어 확인해야 한다(아래 "바이너리 문서" 참고).

## 확인 필요 (미확인 — 판정 보류)

아래는 인수인계 시점에도, 이후 조사에서도 확정하지 못한 항목이다. **추측으로 메우지 말 것.**

- **대성물산 단가 중 어느 것이 지금 유효한지** — `거래처/대성물산/단가표/`의 세 파일이 텀블러
  8,900원(2026-01-10) · 9,200원(2026-04-03) · 9,500원(2026-06-15)으로 다르다. 이름은 작성일로
  정리했지만 실제 현행 단가는 확인하지 않았다. 회의록·이메일과 대조하기 전에는 판정하지 않는다.
- **CS 반품 기간의 최신 확정값** — `CS응대매뉴얼_진짜최종_v2.docx`를 열어야 알 수 있다.
  `반품교환프로세스.md`의 7일은 2025-06 기준 구값이다.
- **CS응대매뉴얼 3세대의 개정일** — 이름 정리는 **보류 중**이다. `반품교환프로세스.md`가 전하는
  "2025년 5월·2026년 7월 개정"은 다른 문서의 전언이지 매뉴얼 자체의 날짜가 아니고, 일자도 모른다.
  본문 개정일을 확인하기 전에는 이름을 바꾸지 않는다(정리 규칙 1번).
- **`CS응대매뉴얼_진짜최종_v2 (1).docx`가 바이트 동일 사본인지** — 크기만 같은 것을 확인했다.
  `md5`/내용 대조 전에는 삭제 금지.
- **매출보고 docx 2종 중 최신본** — 파일명("_최종")은 이 저장소에서 근거가 되지 않는다.
  문서 내부 작성일로 판정해야 한다.
- **`거래처/초록별상사_제안서.pptx` ↔ `거래처/초록별상사/신규거래처_소개자료.docx`** — 같은 거래처
  자료가 상위/하위 폴더에 흩어져 있다. 형식이 달라 중복이 아닐 수 있음, 내용 미확인.
- **`2024년 자료(안씀)/예전_거래처_리스트.xlsx`** — 현행 거래처 정보와 중복 가능성. 폴더명이 이미
  "안씀" 상태 표시라 우선순위는 낮다.
- **DSM-SP100 재고 -32개의 원인** — 반품 처리 지연 관련 가능성만 기재돼 있다.
- **초록별상사 샘플 회신 여부** — 2026-09-05 미팅 이후 진행 상황을 아는 담당자가 없다.
- **`거래처/새 거래처 후보/스캔0002.pdf`** — 이름만 봐서는 무엇인지 알 수 없다. 내용 미확인.

참고: `보고서/매출데이터_2026Q2.csv`와 `카테고리별_매출현황_2026Q2.html`은 중복이 아니라 같은
데이터의 두 표현(원자료 ↔ BI 내보내기)이며, 품번별 합계가 카테고리 합계와 일치함을 확인했다.

## 파일 명명 관행 (읽는 법)

- `최종`, `진짜최종`, `v2`, `- 복사본`, `(수정)`, `(초안)` 접미사는 **버전 순서를 나타내지 않는다.**
  파일 내부의 `작성일`/`비고` 컬럼, 회의록 날짜, 이메일 Date 헤더로 판단할 것.
- 단가표 CSV 스키마는 거래처 공통: `품번,품명,단가(원),MOQ(개),리드타임(일),작성일,비고`.
  `작성일` + `비고`가 사실상 버전 메타데이터 역할을 한다.
- 회의록 파일명은 `YYYY-MM-DD_주제.md`. 이 규칙을 안 지킨 파일(`회의록(수정).md` 등)은
  잘못 놓인 파일일 가능성이 높다.
- 정리를 마친 파일은 `종류/YYYY-MM-DD.확장자`를 따른다(아래 "정리 규칙" 1번). 현재 이 규칙이
  적용된 것은 대성물산 단가표 3개(`거래처/대성물산/단가표/`)뿐이다. 한빛리빙 `단가표.csv`는 버전이 하나뿐이라, CS응대매뉴얼은
  개정일 미확인이라 아직 옛 이름 그대로다.

## 정리 규칙 (2026-10-05 확립)

대성물산 단가표를 정리하면서 정한 규칙이다. 앞으로의 정리 작업은 여기에 맞춘다.

**1. 파일 이름은 작성일 기준으로 — `종류/YYYY-MM-DD.확장자`**

같은 종류의 판은 종류 이름의 폴더(예: `거래처/대성물산/단가표/`)에 모으고, 파일 이름은 작성일로 한다.
날짜는 반드시 **파일 내부의 근거**(CSV `작성일` 컬럼, 문서 본문의 개정일, 이메일 Date 헤더)에서
가져온다. 파일 생성·수정 시각 같은 파일시스템 메타데이터는 재다운로드·복사 때 바뀌므로 근거가
못 된다. 날짜를 확인하지 못했으면 **이름을 바꾸지 않고 보류한다** — 추측한 날짜를 파일명에 박으면
그게 다시 근거 행세를 한다.

파일명에 `최종`·`진짜최종`·`폐기` 같은 **상태를 넣지 않는다.** 상태는 CSV `비고` 컬럼이나 폴더
위치로 나타낸다. 파일명이 상태를 주장하다 생긴 게 이 저장소의 원래 혼란이다.

**2. 지우는 대신 보관 폴더로 — 원래 폴더 아래 `_보관/`**

내용이 같은 중복본은 삭제하지 않고 원래 폴더 아래 `_보관/`으로 옮긴다(예: `거래처/대성물산/_보관/`).
git으로 복원이 가능해졌어도, 파일이 눈앞에서 사라지면 사람이 이력을 못 따라간다. 옮길 때는
**원래 이름 그대로 옮긴다** — 이름을 바꾸지 않아야 그 사본이 원래 무엇이었는지 알아볼 수 있다.
어디에 있던 사본인지는 "이름 변경 이력" 표에 적는다. 엉뚱한 폴더에 잘못 놓여 있던 사본
(예: `회의록/단가표_최종.csv`)은 내용이 속한 폴더의 `_보관/`으로 보낸다.

`_보관/`에는 **기준본과 내용이 같음을 실제로 대조한 것만** 넣는다. 크기가 같다는 것만으로는
부족하다(그래서 `CS응대매뉴얼_진짜최종_v2 (1).docx`는 아직 옮기지 않았다). 구버전은 중복이
아니라 개정 이력이므로 원래 폴더에 그대로 둔다.

**3. 한 묶음이 끝나면 커밋한다**

"한 묶음"은 한 종류의 자료를 정리한 단위다(예: 대성물산 단가표 전체). 파일을 옮기다 만 상태로
두지 않는다. 커밋에 포함할 것:

- 파일 이동은 `git mv`로 — 이력이 끊기지 않고 diff에 `renamed:`로 남는다
- 커밋 메시지에 **옛 이름 → 새 이름 대응**과 그렇게 판단한 근거
- 같은 커밋에 **CLAUDE.md 갱신**까지 — 경로가 바뀌면 이 문서가 곧바로 낡는다

## 바이너리 문서 다루기

`.docx`, `.pptx`, `.xlsx`는 Read 툴로 열리지 않는다(`.pdf`는 Read로 열리지만 스캔본은 텍스트가
거의 안 잡힌다). 내용이 필요하면 압축 해제 후 XML에서 텍스트를 뽑아야 한다:

```bash
python3 -c "
import zipfile,re
z=zipfile.ZipFile('매뉴얼/CS응대매뉴얼_진짜최종_v2.docx')
x=z.read('word/document.xml').decode('utf8')
print(re.sub(r'<[^>]+>','',re.sub(r'</w:p>','\n',x)))"
```

pptx는 `ppt/slides/slide*.xml`, xlsx는 `xl/sharedStrings.xml` + `xl/worksheets/sheet1.xml`.
샌드박스에서 이 명령은 승인이 필요할 수 있다.

## 작업 시 지켜야 할 것

- 숫자(단가·기간·재고)를 답변에 쓸 때는 **출처 파일명과 작성일을 함께 밝힌다.** 이 저장소에서는
  같은 숫자가 서로 다른 값으로 최소 3벌씩 존재한다.
- 원본 파일의 **내용은 건드리지 않는다.** 이름 변경·폴더 이동은 위 "정리 규칙"에 따라 하되,
  파일 안의 글자를 고치는 일(폐기 표시 추가 등)은 반드시 확인을 받고 한다. 작성일이 이른 판
  (`단가표/2026-04-03.csv` 등)도 인수인계 이력의 일부다.
- 회의록·계약서·이메일은 사실 기록이다. 요약·재구성 산출물은 새 파일로 만들고 원본은 남긴다.
- 미해결 항목을 발견하면 추측으로 메우지 말고 "미확인"으로 표시한다 — 원 작성자도 그렇게 남겼다.
