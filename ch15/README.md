# 3부 예제 — 물려받은 업무 폴더

3부(14~20장)가 처음부터 끝까지 참조하는 가상 업무 폴더다. 살림풍경(주방·생활용품
온라인셀러) MD팀에 새로 합류했다고 가정하고, 전임 김도윤 대리가 타 부서로 이동하며
정리 없이 남기고 간 폴더를 그대로 재현했다.

## 쓰는 법 (15장 시작)

`part3-work-folder/` 폴더가 실습 폴더다. 이름 그대로 작업할 자리(예: `~/Projects/`)에
통째로 복사한 뒤, 맨 위 폴더 여덟 개와 파일 서른여덟 개가 그대로인지 세어 보고 시작한다. 이
저장소의 원본은 그대로 두면 실습을 다시 시작할 기준점이 된다.

## 시나리오

- **회사**: 살림풍경 — 주방·생활용품 전문 온라인셀러
- **역할**: MD(상품기획) — 공급업체(거래처) 관리, 단가 협상, 프로모션 기획, CS 정책 관리
- **전임자**: 김도윤 대리 (2026-09말 타 부서로 이동, 인수인계 문서 없이 폴더만 남음)
- **독자(나)**: 신규 합류 MD. 첫 출근 날 이 폴더를 통째로 전달받았다.

## 폴더 구조 (물려받은 그대로 — 아직 정리 전)

```
거래처/                공급업체별 계약서·단가표·시스템 내보내기 + 뜬금없이 섞인 제안서·스캔본
  대성물산/             단가표 3벌 + 복사본 + 계약서 스캔(.pdf)
  한빛리빙/             계약서·단가표(정상 케이스, 대조군)
  초록별상사/           신규 거래처 소개자료(계약 전)
  초록별상사_제안서.pptx   ← 원래 초록별상사/ 안에 있어야 하는데 거래처/ 루트에 잘못 저장됨
  새 거래처 후보/         이름만 봐서는 뭔지 모를 스캔 파일 하나만 덩그러니
회의록/                거래처 미팅·팀 회의 기록 + misfiled 단가표 사본 + 이름만 바뀐 중복본
보고서/                매출·프로모션 보고 + 버전 갈라진 사본 + 워드/파워포인트 기획안
매뉴얼/                CS 응대·반품교환 프로세스 + OS가 자동으로 만든 "(1)" 중복 파일
메모/                  비공식 메모·이메일 사본·인수인계 쪽지 + 기본값 이름 그대로인 잡동사니 텍스트
재고관리/              판매채널 통합관리 솔루션에서 내려받은 재고 동기화 결과(불일치 미확인 건 방치)
미분류/                뭘로 분류해야 할지 몰라서 그냥 던져둔 폴더(스크린샷 PDF, 못 지운 메모 초안)
2024년 자료(안씀)/       2년 전에 쓰다 만 옛 거래처 리스트, 지금은 틀린 정보인데 안 지워짐
```

파일 형식은 진짜 사무 환경만큼 뒤섞였다. 사람이 쓴 문서(`.md`), 엑셀 표(`.csv`·`.xlsx`),
사내 시스템 내보내기(`.json`), BI 툴 리포트(`.html`), 이메일 사본(`.eml`), 급하게 쓴
메모(`.txt`)에 더해, 실제로 많이 쓰이는 **워드(`.docx`), 파워포인트(`.pptx`), PDF(`.pdf`)**
까지 열리는 진짜 파일로 넣었다. 더미 텍스트가 아니라 실제 MS Word/PowerPoint/PDF 뷰어로
열리고 안에 읽을 수 있는 한글 내용이 실제로 들어 있는 유효한 파일이다(한글 폰트를 임베드해
PDF에서도 텍스트가 정상적으로 보인다).

## 왜 이렇게까지 엉망인가

정리 안 된 업무 폴더는 카테고리 폴더 안에 파일이 가지런히 있는 정도로 끝나지 않는다.
실제로는 이런 것들이 섞여 있다.

- **엉뚱한 폴더에 잘못 저장된 파일**: `회의록/단가표_최종.csv`는 대성물산 단가표와 완전히
  같은 내용인데, 회의 중 첨부파일을 내려받다가 엉뚱한 폴더에 떨어진 것이다.
- **이름만 살짝 다른 복사본**: `단가표_최종 - 복사본.csv`(OS가 복사할 때 자동으로 붙인 접미사),
  `CS응대매뉴얼_진짜최종_v2 (1).docx`(같은 파일을 두 번 내려받아 생긴 중복), `회의록(수정).md`
  (원본 파일명은 그대로 두고 엉뚱한 이름으로 따로 저장한 수정본), `2026_상반기_매출보고_최종.docx`
  (표현만 살짝 다듬고 새 파일로 저장한 버전).
- **기본값 이름 그대로인 파일**: `메모/새 텍스트 문서.txt`처럼 이름을 바꾸지 않고 방치된 파일.
- **분류를 포기한 폴더**: `미분류/`에는 스크린샷을 PDF로 내보낸 파일과, 이미 다른 곳으로
  옮겼어야 했는데 지우는 걸 깜빡한 메모 초안이 남아 있다.
- **몇 년째 안 지워진 죽은 자료**: `2024년 자료(안씀)/`에는 지금은 거래하지 않는 거래처
  (미래상사, 뉴스타패키징)가 아직도 "거래처 리스트"라는 이름으로 남아 있어, 잘못 보면 지금도
  거래 중인 것처럼 착각하기 쉽다.

## 심어둔 문제 (이후 장에서 실제로 다룰 것)

- **대성물산 단가표 3벌(+복사본, +misfiled 사본)**: `단가표_2026상반기.csv`(2026-01-10) →
  `단가표_진짜최종_v2.csv`(2026-04-03, 이름과 달리 6월 합의로 폐기된 4월 임시 협상안) →
  `단가표_최종.csv`(2026-06-15, 실제 최신). 여기에 똑같은 내용의 복사본(`- 복사본.csv`)과
  회의록 폴더에 잘못 저장된 사본까지 있어, 파일이 몇 개인지 세는 것부터 헷갈린다. 파일명만
  보면 "진짜최종_v2"가 맞아 보이지만 날짜·회의록·메모를 대조해야 진짜 최신을 알 수 있다.
- **CS응대매뉴얼 3벌(+OS 중복본)**: `_v1` → `_최종` → `_진짜최종_v2`(2026-07, 실제 최신 —
  이번엔 이름 그대로 최신) 순으로, 이름 규칙이 문서마다 다르게 어긋나 있다는 것 자체가
  함정이다. 여기에 `(1)` 중복본까지 있어 "진짜최종_v2가 두 개면 뭐가 다른 건가" 하는 혼란을
  더한다(내용은 동일).
- **보고서의 오래된 가격 인용**: `프로모션_성과분석_추석특가.docx`가 이미 바뀐 구버전 단가
  (8,900원)를 인용하고 있다.
- **미완성 인수인계(그것도 두 군데에)**: `메모/인수인계_해야할것.txt`는 급하게 남긴 미완성
  메모로 "확인 필요"만 적혀 있고 정답은 알려주지 않는다. 그런데 `미분류/김도윤_인수인계전_메모.txt`
  라는 초안이 지워지지 않은 채 따로 남아 있어, 어느 게 최신 인수인계 메모인지도 헷갈린다.
- **교차 확인 단서(3중)**: `회의록/2026-06-10_긴급_단가조정건.md`, `메모/이메일_대성물산_단가협상.eml`,
  `미분류/스크린샷_카톡대화_대성물산.pdf`(카카오톡 대화 스크린샷) 세 개가 각각 독립적으로
  `단가표_최종.csv`의 숫자(9,500원)를 뒷받침한다(`메모/단가협상_메모_대성물산.txt`는 보조 정황). 문서 하나만 보지 않고 여러 원본을 대조해야
  확신할 수 있다는 것을 세 갈래로 보여준다. 18장의 검증이 "단가가 적정한가"(도메인 판단)가
  아니라 "문서들이 어느 값을 말하는가"(문서 정합성 — 도메인 지식 불요)인 이유가 이 구조다.
- **시스템 내보내기의 불일치**: `재고관리/재고동기화_결과_20260630.csv`(판매채널 통합관리
  솔루션에서 내려받은 결과 파일)에 실리콘 뒤집개(DSM-SP100) 재고가 32개 차이 나는
  불일치 건이 "미확인" 상태로 방치돼 있다. 폴더 안 문서만으로는 결론이 나지 않아 사람
  확인으로 넘겨야 하는([모름] 태그) 대표 사례로 설계했다.
- **엉뚱한 위치의 파일**: `거래처/초록별상사_제안서.pptx`(제자리를 벗어난 제안서),
  `거래처/새 거래처 후보/스캔0002.pdf`(이름만 봐서는 뭔지 알 수 없는 스캔 파일)처럼, 폴더
  구조를 믿고 위에서 아래로만 훑으면 놓치는 파일들이 있다.
- **발견되지 않은 신규 거래처 리드**: `거래처/새 거래처 후보/스캔0002.pdf`를 열어보면 실제로는
  "그린테이블(GreenTable)"이라는 친환경 대나무 도마·식기 제조사의 소개자료다. 2026 리빙페어에서
  받은 자료를 스캔만 해두고 폴더 이름도, 후속 연락도 남기지 않은 채 방치된 진짜 리드다 —
  `거래처/초록별상사/` 같은 정식 후보 폴더로 승격된 적이 없어 전임자 외엔 아무도 존재를
  모른다.

각 장은 이 폴더를 실제로 인벤토리(15장)하고, 정리(16장)하고, 위키로 구조화하며 MCP로
바이너리 문서까지 편입(17장)하고, 모순을 검증(18장)하고, 대시보드로 보여주고(19장),
운영 습관으로 계속 살아 있게 만드는(20장) 순서로 다룬다. 각 장을 시작할 수 있는 상태는
이 저장소의 `ch16/`~`ch20/` 폴더에 스냅샷으로 있다.

## 심어둔 문제 → 회수하는 장 매핑

심어둔 문제는 전부 본문 어딘가에서 실제로 풀린다. 회수되지 않고 방치되는 문제는 없다.

| 심어둔 문제 | 회수하는 장 |
| --- | --- |
| 대성물산 단가표 3벌(+복사본·misfiled 사본) | 15장 목록화 → 16장 이름 정리 → 18장 3중 교차검증으로 9,500원 확정 |
| CS응대매뉴얼 3벌(+OS 중복본) | 15장 목록화 → 16장 이름 정리 시도(워드라 보류 — 바이너리 벽 발견) → 17장 스크립트로 뚫어 정리 완료 → 18장 확정 |
| 보고서의 오래된 가격 인용(8,900원) | 18장 두 번째 검증 사례 |
| 미완성 인수인계 메모(두 군데) | 14장 인용(실감 장치) → 15장 확인 필요 목록 |
| 교차 확인 단서 3중(회의록·이메일·카톡 PDF) | 18장 3중 교차검증의 근거 |
| 재고 동기화 32개 불일치(미확인 방치) | 15장 확인 필요 목록 → 18장 [모름] 태그 → 20장 주간 브리핑 "챙길 것"으로 부상 |
| misfiled 파일(제안서 pptx, 스캔0002.pdf) | 15장 확인 필요 목록 → 17장(스캔0002 정체 확인·위키 등재, 제안서 pptx는 MCP 일괄 편입 때 제자리 이동) |
| 그린테이블 신규 리드(스캔0002.pdf의 정체) | 17장 PDF 읽기로 발견, 위키 신규 거래처 후보로 등재 |
| 2024년 죽은 거래처 리스트 | 15장 확인 필요 목록(오해 소지 명시) → 17장 MCP 일괄 편입 때 "과거 자료" 표시로 위키 반영 |
