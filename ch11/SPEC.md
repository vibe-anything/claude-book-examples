# 아침 투자 브리핑 비서 사양(SPEC)

> **확정(v1.0) · 2026-07-24**

인터뷰에서 확정한 결정 사항.

## 1. 문제와 사용자
- **사용자**: 삼성전자·애플을 관심 종목으로 두고 매일 지켜보는 개인 투자자
- **문제**: 두 종목의 관련 뉴스를 매일 여러 곳에서 따로 찾아봐야 함
- **원하는 것**: 평일 아침(7시)에 A4 한 장 분량으로 핵심만 추린 브리핑을 자동으로 받아 보기

## 2. 만들지 않을 것 (이번 범위 밖)
- 관심 종목의 **시세·수익률** 표시(별도 표·위젯·차트)
- **차트·시세 위젯** 등 대시보드 내 시각화
- **카카오톡 등 메신저 알림**
- **매매(매수·매도) 추천**
- **의견·전망성 코멘트** (사실 요약만 함)
- **유료·구독 데이터 소스**
- **지수·환율 등 시장 수치** 정리 (브리핑은 종목 뉴스만 다룸)

## 3. 완료 기준 (Definition of Done)
1. 아침에 브리핑 문서가 자동으로 생겨 있다.
2. 대시보드에서 지난 브리핑을 볼 수 있다.
3. 공개 URL로 접속된다.

## 4. 데이터
- **뉴스 출처**: NAVER API HUB의 뉴스 검색 API
- **뉴스 수집량**: 종목당 **최대 5건까지 수집**, 브리핑에는 중요한 것 위주로 추려 노출
- 유료·구독 소스는 사용하지 않음

## 5. 브리핑 문서 형식
- **종목마다** 세 부분
  1. **어제 나온 뉴스 요약**: 3~5건, 한 줄씩
  2. **오늘의 체크 포인트**: 내가 눈여겨볼 것 1~3개
  3. **원문 링크**: 요약이 의심되면 눌러서 확인(요약마다 원문 기사 링크)
- **발행**: 평일 오전 **7시(KST)**
- **톤**: 본문 **전부 개조식**(명사형 종결)
- **분량**: A4 한 장(3분 내외)
- **체크 포인트**: 사실 기반(모은 기사에서 나온 것만), 의견·면책 문구 없음
- **표기**: 시각·날짜 KST 기준

## 6. 파일 구조
```
briefing-assistant/   # 이 폴더가 곧 Next.js 앱(대시보드)
├─ SPEC.md            # 사양(본 문서)
├─ briefings/         # 날짜별 생성 결과 (예: 2026-07-24.md)
├─ app/               # 대시보드 화면 (브리핑 열람)
├─ lib/               # briefings/ 읽기
└─ package.json       # Next.js 앱 설정
```

## 7. 대시보드 화면
- **Next.js**로 구현. 하위 폴더 없이 프로젝트 폴더를 그대로 앱으로 쓴다(폴더가 곧 앱)
- **오늘 브리핑이 맨 위**: 당일 브리핑 전문(全文)을 렌더링해 표시
- **종목별 카드**: 종목마다 브리핑을 카드 하나로 나눠, 지난 브리핑 목록과 한 화면에 표시
- **지난 브리핑**도 날짜별 목록에서 골라 열람
- **공개 URL**로 접속 가능
- 차트·시세 위젯은 넣지 않음

## 8. 만드는 순서
각 단계 끝에 **눈으로 보거나 실행해 확인**할 수 있게 구성. 대시보드가 처음부터 `briefings/*.md`를 읽는 구조라, 목 데이터가 실제 브리핑으로 바뀌어도 화면 코드는 그대로 유지됨.

1. **대시보드 화면 프로토타입** (실데이터 없음): Next.js로 화면 구조만. SPEC 브리핑 형식에 맞춘 목 데이터 `.md` 몇 개 사용.
   - 확인: 브라우저에서 종목별 화면, 브리핑 형식(요약·체크 포인트·원문 링크) 자리, 지난 브리핑 목록을 눈으로.
2. **뉴스 데이터**: NAVER API HUB의 뉴스 검색 API로 종목 뉴스 수집.
   - 확인: 한 번 호출해 기사 제목·발행 시각·원문 링크가 실제로 오는지.
3. **브리핑 생성**: 모은 뉴스를 SPEC 형식대로 정리해 `briefings/YYYY-MM-DD.md`로 저장. 목 데이터는 삭제.
   - 확인: 원문 링크가 실제 기사로 열림 + 대시보드 맨 위에 오늘 브리핑.
4. **매일 아침 자동 실행**: 두 종목을 처음부터 끝까지 한 번 돌려 본 뒤 정해진 시각에 반복 등록. 반복은 브리핑 생성까지, 커밋·푸시는 사람이 확인 후 직접.
   - 확인: 시험 실행으로 브리핑 생성까지 성공.
5. **배포**: 대시보드를 공개 URL로 배포.
   - 확인: 휴대폰에서 공개 URL 접속 → 완료 기준 3항목 대조.
