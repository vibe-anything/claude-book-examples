# 종목 뉴스 브리핑 수집 (news)

종목 하나(또는 여러 개)의 이름을 입력받아, **네이버 뉴스 검색 API**로 최근 뉴스를 모으고
`SPEC.md`의 브리핑 형식대로 정리해 `briefings/<오늘>.md` 에 저장한다.

**핵심 규칙: 하루에 파일 하나.** 같은 날짜 파일이 이미 있으면 새로 만들지 말고,
해당 종목의 `## <종목>` 블록만 **추가하거나 갱신**한다.

## 입력
- **종목 이름**(필수): 예) `삼성전자`, `애플`. 여러 개면 각 종목에 대해 아래 절차를 반복.

## 사전 조건
- 프로젝트 루트 `.env` 에 `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` 가 채워져 있어야 한다.
  - 값이 비어 있으면 중단하고, NAVER API HUB(console.ncloud.com)에서 뉴스를 고른 Application의 Client ID·Client Secret을 `.env` 에 넣도록 사용자에게 안내한다.
- 모든 경로는 프로젝트 루트 기준(`briefings/`, `.env`).

## 절차

### 1. 오늘 날짜(KST) 확정
```bash
TZ=KST-9 date +%Y-%m-%d      # 파일명용 (예: 2026-07-24)
TZ=KST-9 date "+%Y-%m-%d (%a) %H:%M KST"   # 헤더 작성 시각용
```
날짜·시각은 반드시 한국 시간(KST, UTC+9) 기준. 파일명은 `briefings/<YYYY-MM-DD>.md`.

### 2. API 키 로드 + 뉴스 검색
`.env` 를 읽어 종목명으로 뉴스를 검색한다. 한글 종목명은 명령 인자로 넘기지 않고 `printf`로 curl의 표준 입력에 넘겨 `--data-urlencode "query@-"`로 인코딩한다(Windows Git Bash의 curl은 명령 인자의 한글을 UTF-8로 받지 못한다).
```bash
set -a; source .env; set +a
printf '%s' "<종목명>" | curl -s -G "https://naverapihub.apigw.ntruss.com/search/v1/news" \
  --data-urlencode "query@-" \
  --data "display=10" \
  --data "sort=date" \
  -H "X-NCP-APIGW-API-KEY-ID: $NAVER_CLIENT_ID" \
  -H "X-NCP-APIGW-API-KEY: $NAVER_CLIENT_SECRET"
```
- `sort=date`(최신순)로 받은 뒤, 종목과 무관하거나 중복인 기사는 걸러낸다.
- 직전 브리핑 날짜 이후에 나온 기사만 남긴다(직전 브리핑이 없으면 최근 하루치). 직전 브리핑은 `briefings/`에서 오늘보다 앞선 가장 최근 파일이고, 기사 날짜는 `pubDate`로 본다.
- 이전 브리핑에 이미 실린 기사는 다시 넣지 않는다(비교 대상에서 오늘 만드는 파일 자신은 제외한다). 같은 기사인지는 원문 링크로 가린다.
- **종목당 최대 5건**까지만 브리핑에 노출(SPEC §4). 중요한 것 위주로 추린다.
- 응답 `items[]` 필드: `title`, `originallink`, `link`, `description`, `pubDate`.
  - `title`·`description` 의 `<b>` 태그와 HTML 엔티티(`&quot;`, `&amp;` 등)는 제거해 평문으로.
  - 링크는 `originallink`(원문) 우선, 없으면 `link` 사용. **원문 링크를 반드시 함께 남긴다.**

### 3. 종목 블록 작성 (SPEC 형식)
아래 형식의 `## <종목>` 블록을 만든다.
```markdown
## <종목> (수집: HH:MM KST)

### 어제 나온 뉴스 요약
- <한 줄 요약> ([출처](<원문 링크>))
- ... (3~5건)

### 오늘의 체크 포인트
- <눈여겨볼 것> (1~3개)
```
- 톤: **개조식(명사형 종결)**. 본문 전부.
- **사실 요약만**. 의견·전망·매매(매수/매도) 추천·면책 문구 금지(SPEC §2, §5).
- 체크 포인트는 위에서 모은 기사에서 나온 것만 쓴다.
- 시각·날짜는 KST.
- **시세 표·차트는 넣지 않는다**(비범위). 뉴스 본문 속 수치는 텍스트 맥락으로만.

### 4. 저장 / 갱신 (하루 한 파일)
`briefings/<오늘>.md` 존재 여부로 분기한다.

- **파일 없음** → 아래 머리 뒤에 지금 종목의 `## <종목>` 블록을 붙여 새로 만든다.
  ```markdown
  # 아침 투자 브리핑 <YYYY-MM-DD> (<요일>)

  작성 시각: <HH:MM> KST

  <여기에 ## <종목> 블록>
  ```
- **파일 있음** → 같은 `## <종목>` 헤더를 찾는다.
  - **있으면**: 그 헤더부터 다음 종목 헤더(`## `로 시작하는 줄) 직전(없으면 파일 끝)까지를 새 블록으로 **교체(갱신)**.
  - **없으면**: 파일 끝에 새 블록을 **추가**.
  - 다른 종목 블록은 **건드리지 않는다**.

### 5. 보고
저장한 파일 경로, 갱신/신규 여부, 수집 건수를 사용자에게 보고한다.
커밋은 하지 않는다(작업 규칙: 사용자 확인 후 커밋).

## 주의
- `.env` 값과 API 응답 원문을 브리핑 파일에 그대로 노출하지 않는다(키 유출 방지).
- 여러 종목을 처리할 때도 파일은 하나. 종목별로 4단계를 반복해 같은 파일을 갱신한다.
- API 오류(인증 실패 401, 한도 초과 429 등)면 중단하고 원인을 사용자에게 알린다.
